# Algorithm Bridge 학습 사다리 설계

## 1. 설계 목적

이 문서는 [book-problem-approaches.md](book-problem-approaches.md)의 난이도 `★`·`★★` 문제 63개를 분석해, 책 문제를 복제하지 않으면서도 풀이를 시작할 수 있게 만드는 Bridge 문제의 학습 순서와 필요한 근거를 정한다.

문제 수를 먼저 정하지 않는다. 새 문제는 다음 중 하나를 추가로 증명할 때만 만든다.

1. 아직 연습하지 않은 `접근 원자`를 처음 사용한다.
2. 이미 익힌 두 원자를 새로운 순서로 연결하는 `접근 연결`을 연습한다.
3. 힌트를 줄인 처음 보는 문제에서 스스로 접근을 고르는 `전이 증거`를 만든다.

같은 판단을 숫자나 이야기만 바꿔 반복하면 새 문제로 세지 않는다.

## 2. 사다리 단계

| 단계 | 학습자가 하는 일 | 문제 지원 |
|---|---|---|
| L0 관찰 | 작은 Java 예제의 값과 데이터 흐름을 손으로 따라간다. | Guide 예시이며 풀이 문제 수에 넣지 않는다. |
| L1 한 가지 행동 | 한 접근 원자를 사용해 작은 결과를 만든다. | 생각 질문과 작은 단계부터 시작하는 힌트를 제공한다. |
| L2 행동+조건 | 같은 원자에 경계, 원본 보존, 동점 같은 실제 조건을 더한다. | 접근 방식은 접고, 필요한 경우에만 단계별 힌트를 제공한다. |
| L3 접근 조합 | A를 끝낸 결과를 B의 입력으로 쓰는 순서를 스스로 나눈다. | 질문은 제공하되 힌트 수를 줄인다. 접근 조합은 접어 둔다. |
| L4 전이 확인 | 처음 보는 작은 문제에서 단서→개념→이유→데이터 흐름→의사 코드→Java 구현을 스스로 시작한다. | 풀이 힌트를 제공하지 않는다. 접근 방식은 구현 후 비교용으로만 접어 둔다. |

한 접근 원자가 쉬우면 L1과 L2를 한 문제에 합칠 수 있다. 반대로 원자는 알아도 연결 순서가 새롭다면 L3 문제를 별도로 둔다. 모든 단계를 억지로 한 문제씩 만들지 않는다.

## 3. 문제 수 계산 방법

주제마다 다음 세 집합을 계산한다.

- `A`: 책 문제를 시작하는 데 필요한 접근 원자
- `E`: 원자 A의 결과를 원자 B에 넘겨야 하는 순서 있는 연결
- `T`: 설명 없이 접근을 선택할 수 있음을 확인할 접근 계열

후보 한 개가 `A`, `E`, `T` 중 새로운 항목을 하나도 덮지 않으면 제거한다. 하나의 문제가 서로 가까운 원자와 연결을 자연스럽게 함께 덮으면 합친다. 단, 초보자가 어느 행동부터 해야 할지 보이지 않을 정도로 한꺼번에 묶지 않는다.

초기 설계는 68개 슬롯이다.

| 주제 | 초기 슬롯 | 계산 근거 |
|---|---:|---|
| 배열 | 12 | 이미 구현된 기초 7개 + 정렬·중복·쌍·반복 패턴·2차원 교차 처리 5개 |
| 스택 | 5 | 짝 확인, 역순 복원, 원형 검증, 미해결 인덱스, 여러 스택 파이프라인 |
| 큐 | 4 | 회전, 조건부 제거, 앞 작업 장벽, 두 머리 선택 |
| 해시 | 6 | 포함·빈도·고정 창·안정 ID·그룹 집계·관계 역전파 |
| 트리 | 4 | 자식 인덱스, 방문 시점, 부모 수렴, 부모 사슬 누적 |
| 집합 | 4 | `HashSet` 2개 계열 + 유니온-파인드 2개 계열 |
| 그래프 | 6 | 표현·DFS, BFS 거리, 격자, 연결 요소, 경유지, 후위 집계 |
| 백트래킹 | 5 | 선택·취소, 시작 위치·가지치기, 순열 자원, 충돌, 완성 채점 |
| 정렬 | 6 | 빈도, 두 포인터, 복합 기준, 변환, 인접화, 파싱 조합 |
| 시뮬레이션 | 6 | 후보 상태, 좌표 변환, 경계 축소, 반복 상태, 이동 경계, 후보 검증 |
| 동적 계획법 | 4 | 주어진 점화식, 점화식 도출, 2차원 방향, 금지 전이 |
| 그리디 | 6 | 정당성, 싼 접두, 비율, 양끝, 빈도 묶음, 구간 점프 |
| 합계 | **68** | 고정 목표가 아니라 아래 슬롯의 서로 다른 학습 근거 합계 |

68은 채워야 하는 성과 숫자가 아니다. 생성·검증 과정에서 두 슬롯이 같은 판단이라는 근거가 확인되면 합치고, 책 문제를 시작하는 데 필요한 연결이 빠졌다는 근거가 확인되면 설계를 먼저 수정한 뒤 추가한다.

### 05 배열 — 12개

기존 `ArrayProblem01`~`07`은 다음 슬롯을 이미 구현한다. 새 생성 작업은 빠진 `ARR-08`~`ARR-12`만 다룬다.

| 슬롯 | 단계 | 접근 방식 또는 조합 | 새 학습 근거 | 연결되는 책 문제 |
|---|---|---|---|---|
| ARR-01 | L1 | 원본 복사 → 지정 위치 수정 → 반환 | 원본과 결과를 분리하고 1부터 세는 위치를 인덱스로 바꾼다. | 01의 원본 변경 판단, 54의 구간 복사 선행 |
| ARR-02 | L1 | 전체 확인 → 범위 조건에 맞으면 개수 증가 | 한 번 순회하며 조건과 개수를 함께 관리한다. | 04의 대상별 집계 선행 |
| ARR-03 | L2 | 이웃 값 비교 → 변화량 배열 생성 | 입력과 결과 인덱스가 다른 새 배열을 만든다. | 58의 이웃 비교 선행 |
| ARR-04 | L2 | 결과 개수 확인 → 새 배열 생성 → 원래 순서대로 저장 | 고정 길이 배열에서 조건부 결과를 두 번 순회해 만든다. | 02의 변환, 23의 결과 배열화 선행 |
| ARR-05 | L3 | 앞에서부터 합을 미리 저장 → 여러 구간을 두 합의 차이로 계산 | 같은 구간 계산을 반복하지 않도록 전처리한다. | 이후 구간 처리의 전이 경험 |
| ARR-06 | L4 | 현재 연속 길이와 최장 길이를 함께 갱신 | 힌트 없이 이웃 비교와 두 상태를 고른다. | 연속 상태 문제의 전이 확인 |
| ARR-07 | L1 | 행마다 값 누적 → 같은 행 번호의 결과에 저장 | 길이가 다른 행을 포함한 2차원 반복을 익힌다. | 05·60의 행 처리 선행 |
| ARR-08 | L2 | 원본 복사 → 정렬 → 정렬 결과로 한 개의 파생값 계산 | 정렬 배열 자체를 답으로 내지 않고 정렬을 중간 도구로 쓴다. | 01 |
| ARR-09 | L2 | 앞에서부터 확인 → 처음 본 값만 원래 순서대로 반환 | 중복 제거와 출력 순서를 따로 판단한다. 내림차순 결과는 만들지 않는다. | 02 |
| ARR-10 | L3 | `i < j`인 모든 쌍 확인 → 추가 조건 판정 → 하나의 통계 반환 | 서로 다른 인덱스 쌍과 중복 결과 목록 생성을 분리한다. | 03 |
| ARR-11 | L3 | 반복 패턴 조회 → 여러 개수 누적 → 기준을 넘긴 대상만 반환 | `%`, 여러 카운터, 결과 선택을 순서대로 연결한다. 최고 득점자 문제는 만들지 않는다. | 04 |
| ARR-12 | L3 | 2차원 크기 확인 → 행과 열을 교차해 누적 → 1차원 요약 반환 | 행 하나와 열 하나를 대응시키되 행렬 곱 결과는 만들지 않는다. | 05 |

문제 06 실패율은 `배열+해시+복합 정렬`, 문제 07 방문 길이는 `좌표 시뮬레이션+집합`이 준비된 뒤 교차 주제 전이로 확인한다.

## 6. 책 문제와 다르게 만드는 최소 기준

DFS, BFS, 유니온-파인드, 백트래킹처럼 표준 알고리즘의 골격은 학습 목적으로 공유할 수 있다. 그러나 다음 다섯 차원을 문제마다 비교한다.

1. 소재
2. 목표와 반환 결과
3. 입력·출력 구조
4. 제약과 추가 조건
5. 접근 조합과 결과 생성 흐름

책 문제로 접근 경험을 옮기기 위해 핵심 접근 원자와 순서 있는 연결은 의도적으로 공유한다. 같은 풀이 골격을 사용한다는 사실만으로 중복으로 판정하지 않는다.

소재만 바꾼 것은 독립 문제가 아니다. 생성 문제는 책 문제와 `목표·반환 결과`가 달라야 하고, `입력·출력 구조` 또는 `제약·추가 조건` 중 적어도 하나도 의미 있게 달라야 한다. 이름·소재·상수 또는 출력 형식만 작게 바꿔 책 정답 코드를 거의 그대로 재사용할 수 있으면 폐기한다.

## 7. 주제 완료 판정

다음 조건을 모두 만족할 때만 해당 주제의 브릿지가 완료된다.

- 해당 주제의 필수 접근 원자를 모두 한 번 이상 실제 Java 코드로 사용했다.
- 필요한 순서 있는 접근 연결을 모두 한 번 이상 구현했다.
- 같은 판단만 반복하는 문제가 없다.
- 각 접근 계열에 L4 전이 문제 또는 그에 준하는 힌트 없는 검증이 하나 이상 있다.
- 학습자가 L4에서 핵심 단서, 선택한 개념, 선택 이유, 데이터 흐름과 의사 코드를 설명한 뒤 구현을 시작할 수 있다.
- 관련 책 문제를 복제하지 않았다는 다섯 차원 비교 기록이 남아 있다.
- 정답 코드가 컴파일되고, 제약에서 고른 서로 다른 범위·경계 테스트가 모두 통과한다.

정답률이나 문제 개수만으로 완료를 판정하지 않는다.
